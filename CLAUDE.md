# Chro

AI-powered productivity desktop application.

## Architecture

```
apps/
  desktop/    → Electron + Vite + React 19 + TanStack Router (main product)
  api/        → Cloudflare Workers (Rust → WASM, D1 database)

packages/
  ui/         → Shared components (Radix UI + Tailwind CSS)
  kv/         → Key-value storage utilities

crates/       → Rust backend (15 crates)
  server/     → Axum web server (local, SQLite, JSON-RPC/WebSocket)
  db/         → SQLx + SQLite ORM layer
  ...         → approvals, config, diff-stream, events, executors,
                file-search-cache, filesystem, git, image, local-runtime,
                log-types, runtime, worktree

tooling/
  scripts/    → Build & deployment scripts
  typescript/ → Shared TS config
```

## Commands

```bash
# Development
bun dev:web          # Marketing web app (@chro/web)
bun dev:web:perf     # Desktop frontend + Rust with perf recording to log/performance/
bun dev:desktop      # Full desktop (Vite + Electron + Rust server)
bun run --filter=@chro/desktop dev:web  # Desktop frontend only (Vite, port 3400)
bun dev:api          # Cloudflare Workers API (port 5286)

# Build & Test
bun run build        # Build all
bun run test         # Run tests (Vitest)
bun run typecheck    # TypeScript check
bun run lint         # Biome lint
bun run format       # Biome format

# Rust server (standalone)
cargo run --manifest-path crates/server/Cargo.toml --bin chro-server -- --port 4310
```

- `apps/desktop` dev server proxies `/rpc`, `/streams`, `/health`, `/sessions`, `/tasks` to the Rust backend
- Backend port is dynamic, read from `/tmp/chro/chro.port`
- Route tree is auto-generated by TanStack Router plugin (`routeTree.gen.ts` is gitignored)

## Performance Profiling

### Automated recording (`bun dev:web:perf`)

`bun dev:web:perf` starts Vite + Rust server with performance recording enabled.
Logs are written to `log/performance/` (gitignored) in JSONL format:

- `YYYY-MM-DD_frontend.jsonl` — Web Vitals (LCP, FCP, CLS, INP), long tasks, slow resources, memory samples
- `YYYY-MM-DD_backend.jsonl` — RPC summaries, slow request details, backend action events

Both frontend and backend log files rotate at 50,000 lines (`YYYY-MM-DD_backend.1.jsonl`, etc.).

`frontend` には `type: "ui-action"` の操作イベントも出力される（例）:
- `session_send_start/end`, `session_task_run_started`
- `task_run_stream_opened`, `task_run_first_patch`, `task_run_stream_stalled`, `task_run_stream_finished`
- `session_switch_start/end`
- `workspace_tree_root_load_start/end`, `workspace_tree_initialization_start/end`, `workspace_tree_ready`
- `editor_mount_start/end`, `editor_content_reset_start/end`

`backend` には以下の type が出力される:
- `rpc_summary` — 30秒ごとのエンドポイント別集計 (count, avg_ms, min_ms, p95_ms, max_ms)。パス中のUUIDは `{id}` に正規化される
- `rpc_slow` — 200ms超の個別リクエスト (method, path, path_pattern, status, duration_ms, request_id)
- `backend-action` — 詳細イベント:
  - `execution_request_received/completed/failed` (`kind: start|follow_up`)
  - `task_run_logs_stream_opened`, `task_run_logs_stream_first_patch`, `task_run_logs_stream_stalled`, `task_run_logs_stream_finished`, `task_run_logs_stream_closed`

`rpc_slow` と `rpc_summary` には `request_id` / `endpoint` が含まれ、`frontend` の `session_send_*` と突合できる

Implementation:
- Frontend: `apps/desktop/src/perf/recorder.ts` collects PerformanceObserver data, flushes to Vite dev server `/perf/report` every 30s
- Backend: `crates/server/src/perf.rs` Axum middleware with RPC aggregation (30s interval) + slow request logging (>=200ms), enabled by `--perf` CLI flag
- Vite: `CHRO_PERF=1` (or `--perf` if passed through) activates the `chro-perf` plugin (`__PERF_ENABLED__` define)
- File rotation: both frontend/backend rotate at 50,000 lines per segment

### Manual analysis

- `bun run --filter=@chro/desktop dev:web:scan` launches react-scan overlay for render analysis
- react-scan is browser-overlay only; no automated recording
- Key metrics to track:
  - **Rendering**: re-render counts, component render duration (react-scan, React Profiler API)
  - **Bundle**: JS/CSS chunk sizes, code splitting effectiveness (vite-bundle-analyzer)
  - **Runtime**: long tasks, memory usage, WebSocket throughput
